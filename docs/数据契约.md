# 《奶龙：银河征途》数据契约（M0）

> 适用范围：v1.1 范围收窄版（⓪①② 三区域 / 15 房）。
> 所有权：本文件描述的六张数据表归 **Level/Balance Agent** 所有，代码侧（Architect/Gameplay）只读。
> 参考章节：开发计划书 §3.3 / §3.5–3.8 / §4.1–4.4 / §5.1–5.2 / 附录 A/B。

## 0. 总则

1. **严格 JSON**：UTF-8、无注释、无尾逗号、键带双引号。说明文字只写在本文档，不写进 JSON。
2. **一切数值进表**：代码里禁止魔法数字；改数值 = 改表 + 跑校验，不动脚本。
3. **单位**：坐标/尺寸为像素（px），速度为 px/s，时间为秒（s），`*_pct` 为百分数（如 `15` 表示 +15%，`-10` 表示 -10%），`resist` 为百分比减伤（0=正常伤害，100=免疫），物理与奶术分别结算，不受区域倍率影响。
4. **校验命令**：`python3 tools/qa/validate_data.py`，退出码 0 才允许提交（覆盖断言见第 9 节）。

## 1. 坐标与几何约定（全表通用）

| 事项 | 约定 |
|---|---|
| 房间像素尺寸 | `size = [w,h]`，实际像素 `W = w×640`、`H = h×360`；本期只允许 1×1 / 2×1 / 1×2 / 2×2 |
| 平台矩形 | `[x,y,w,h]`，矩形完全在房间边界内；**顶面 y 是可站立面**，渲染为 `_draw()` 灰盒色块 |
| 玩家碰撞体 | 20×34（半宽 10 / 半高 17，§2.5） |
| 站立点约定 | 角色类坐标（spawn、门 pos、地面敌人 pos、检查点 pos）= **碰撞体中心**，站立时 `y = 平台顶 - 17` |
| 宝箱 | 视为 24×20 盒子，pos = 中心，放置时 `y = 平台顶 - 10` |
| 门 pos | 见 §2.3；n/s 门也要求落在平台上（站在高台/地面，贴上下边） |
| map_rect | `[x,y,w,h]` 小地图格坐标（1 格 = 640×360），两两互不重叠，w/h 与 size 一致 |
| 跳跃可达参考 | 单跳升 ≈56px；平台台阶升 ≤48 视为单跳可上；升/横距 >56~90 视为需二段跳（数值以 Gameplay 实测为准，数据层只负责放置） |

### 2.3 doors[]：门与配对语义

门对象：`{id, pos, target, target_door, one_way, requires}`。

| 字段 | 类型/枚举 | 语义 |
|---|---|---|
| id | 方位惯例 | 前缀 `w/e/n/s`，同方位多门加数字后缀（如 `e2`） |
| pos | [x,y] | 玩家进入/落地的站立点。w 门 `[0,y]`、e 门 `[W-10,y]`；n 门贴上边（y≤48，站高台）、s 门贴下边（y≥H-48，站地面） |
| target | string | 目标房间 id |
| target_door | string | 目标房间里的门 id |
| one_way | bool | **true = 该门只能作为单向通道的落点，不可从此侧主动进入**（AGENTS.md §6 约定） |
| requires | "" \| "double_jump" | 能力门：未解锁该能力时门锁定（锁标+提示） |

**配对规则（校验脚本强制）**：

- 每个门与它的 `target.target_door` 必须**互指**（你指我、我指你），且方位**互补**（w↔e、n↔s）。
- 双向门：两侧 `one_way` 均 `false`。
- **单向捷径**（本期唯一一处，cave_07→camp_01）：cave_07 侧门 `s`（`one_way:false`，可通行）→ camp_01 侧落点门 `n`（`one_way:true`，锁定，仅作落点，指回 cave_07.s）。玩家击败女王后从 cave_07 落回营地，不能反向钻回洞窟。
- **能力门**（本期唯一一对）：forest_03.n ↔ forest_06.s 两侧 `requires:"double_jump"`；其余门一律 `requires:""`。二段跳来自 cave_07 宝箱（击败蜂蜜女王后）。
- 门的进出落点都要求站在平台上；SceneRouter 切房后把玩家放到目标门 pos（对齐误差 ≤4px 由代码保证）。

## 5. data/weapons.json

顶层 `{"weapons":[...]}`，当前 20 条（18 把现役及 2 条旧档兼容）。全部 ID、数值、效果与描述见[武器登记表](gameplay/武器登记表.md)。

统一字段：`id, name, weapon_type(sword/hammer/staff/rifle), damage_type(physical/magic), range_type(melee/ranged), attack, poise_multiplier, attack_speed_multiplier, combo, desc, appearance_id, special_effects`。

`attack_speed_multiplier`为正有限数值；实际攻击动作时间为类别基础时间除以攻速倍率，倍率大于1更快、小于1更慢。起手、判定、收招和逐帧表现同步换算；原定倍率数值不取倒数存储。`attack_interval`已停用。类别基础时间与各段基础削韧在`data/weapon_attributes.json`；普通攻击削韧仍为基础削韧乘`poise_multiplier`。技能保持独立时间与削韧配置。

`appearance_id` 选择独立外观。`special_effects` 的实装状态用 `implemented:true` 登记，未实现的武器技能用 `implemented:false`。`knockback` 单位为 px/s 初速，武器 ID 保存在存档。

枪类 `ammo_cost_pct` 是每次射击消耗的储量百分比。基准射击间隔为 1 秒，除以有效攻速倍率得到实际间隔。`rifle` 配置保存基础弹速、储量单位和冲击波范围，武器 `special_effects` 保存弹种、散布、弹速倍率、穿透及冲击波伤害比例。`ammo_units` 是存档中的整数储量，1000 对应 100%。

`data/accessories.json` 按稳定 ID 保存饰品的名称、描述、效果和贴图。存档用 `owned_accessories` 保存持有 ID，用 `equipped_accessories` 保存两个装备槽。`data/status_effects.json` 保存流血、中毒和冰缓的跳伤间隔、敌怪等级倍率及特效。异常依附于当前敌怪生命池，持续时间以战斗时间推进。

## 9. 校验脚本（tools/qa/validate_data.py）

python3 运行、零第三方依赖。失败逐条打印 `[FAIL]`，退出码 1；全过打印 64 项 `[OK]`，退出码 0。

## 2026-10-28 成长、格挡与仓库补充

制作人本次决策覆盖旧天赋操作入口。`data/progression.json` 保存五项点数的每级效果、奶能发放和消费数量、属性显示行、仓库分类和相关布局；角色等级原有自然成长仍由 `gameplay_ui.json.growth` 定义。

存档新增 `milk_energy`（未消费奶能）、`attribute_points`（vitality/endurance/strength/intellect/perception 的非负等级）、`permanent_bonuses`（永久道具带来的额外属性）、`progression_revision`（成长存档迁移版本）。旧存档按角色等级补发奶能，并从原有上限中还原永久道具加成。点数仅可在坐火天赋点数页消费，I 属性页只查看。

`data/hero_motion.json.guard` 定义格挡举起帧时长、维持帧、解除时长、默认减伤、体力消耗与反弹比例。精准格挡窗口取举起帧数乘帧时长。`data/guard_frames.json` 定义四类武器共用身体动作，以及每种武器对应的攻击来源和资源校验值；`combat_presentation.json.animations.guard_*` 只加载完整人物 PNG。

仓库继续保存 `storage: [{id,count},...]`，无固定长度上限。道具、材料与快捷道具沿用原物品来源；未装备武器在 `owned_weapons` 与仓库之间搬移。分类筛选保留真实来源与下标，失败不修改任何一方。


## 2026-10-28 十二技能替换

制作人明确以SKL-B01和SKL-NB01十二招替换旧主动与占位，并批准未定参数先用临时值。`skills.json.revision=2`含十二招主动、八条既有被动；主动的`asset_batch`、`weapon_requirement`、`icon`均绑定正式素材，`legacy_aliases`只供旧存档/奖励兼容。试玩期间十二招`unlock=initial`，三个主动槽与两个被动槽数量不变。

`skill_presentations.json.animations`统一两批清单的帧序、原图SHA-256、fps、循环标记、root和attachment。角色脚底映射节点+(0,17)，B01 root为(48,90)、NB01为(48,84)，不能共用偏移。资源按需缓存，禁止重绘原角色或按每帧包围框缩放。

GameState的`skill_buffs`只保留会话状态，不序列化；狂击/忍耐进入实际攻击与承伤及属性加成计算，奥术只转换普通攻击类型。旧主动ID在读档时映射并去重。详见[十二技能接入](gameplay/十二技能接入-2026-10-28.md)。

### 2026-11-06 首领阶段与演出（覆盖上述草案）

`claffert.json.phases`分别保存600/1000基础生命和300/450韧性；区域倍率仍只影响基础生命/攻击。`DataDB.get_boss_for_room(id, room, phase_index)`先选择阶段再解析倍率，阶段韧性覆盖根级默认值。

`data/boss_rules.json.paralysis`定义`base_seconds=1`、`poise_factor=0.01`；所有Boss通过`EnemyStats.paralysis_seconds`取`base_seconds+poise*poise_factor`。Boss定义存在显式`paralysis_seconds`时优先使用该值。普通小怪仍按硬直动作结束回韧，不套用首领公式。

`sequence.transition/defeat`集中保存转阶段CG与最后招式的时间、移动、遮屏、震动、黑洞半径、逐帧损伤及弱引力数值。转阶段只有在全屏紫光不透明时提交二阶段；期间`Player.cinematic_locked`与`GameUI.cinematic_active`共同屏蔽角色及菜单输入。摄像机通过`focus_target`临时跟随Boss，结束恢复原目标。

二阶段生命归零仅开始虚空湮灭；不得立即发送`enemy_died/boss_defeated`。控制器锁存玩家死亡；紫光散去且玩家始终存活才发送一次击败事件。失败不结算，重生后重置遭遇。黑洞接触每物理帧固定损失1生命，不沿用普通受击无敌间隔或每次强制硬直。两阶段仍仅放在独立演练场，正式地图不新增Boss。

### 2026-11-12 落地恢复与地刺预警

`phase2_combat.ground_recovery`定义落地速度、地面物理层、落地后硬直时长4秒和削韧倍率2。近身状态机在招式之间依次进入`land → ground_stagger → reposition`，从脚下真实表面计算花心位置；此恢复窗口不等同于破韧瘫痪。`EnemyPoise.receive(packet, damage_multiplier=1)`仅将本次削韧乘倍率，不改写共享DamagePacket或生命伤害。破韧恢复会跳过残留落地恢复，按既有规则立即接招。

地刺`delay_seconds=1.5`现在表示危险红光消失到第一道尖刺出现的总等待，包含触手入地动作。红光时长/逐帧素材复用`combat_feedback.json.danger_warning`，首道总时刻由`spike_release_seconds()`计算，禁止再额外叠加`bury_seconds`。取消招式、转阶段会立即清掉预警。`sequence.defeat.radius_multiplier=10`同时驱动虚空图像和接触伤害范围。

`grounded_frame=0`与`grounded_bottom=39px`来自既有二阶段闲置首帧的可见下缘；仅用于落地对齐，不改变花心锚点、身体像素或碰撞半径。

### 2026-11-17 土狼时间完善

`data/player_movement.json.jump.coyote_time`保存离台后的普通跳宽限，保持原有0.10秒，经`PlayerTuning.COYOTE_TIME`读取。走出实心或空心平台才开启宽限，成功起跳立即消费；主动起跳、主动下穿及重生不会继承旧宽限。窗口内优先使用普通跳，不消费已解锁的二段跳；过期后仍按原空中跳跃规则判断。

接地后由实际物理结果重置跳跃与空中行动次数，不再仅依赖进入Land状态；因此攻击/技能中落地后再次离台也能正常使用宽限。跳高、短跳、跳跃缓冲时长均保持原值。`test/integration/test_coyote_time.gd`使用真实角色、实体平台和空心平台验收时间边界、输入缓冲、重复起跳、二段跳、攻击中落地、下穿及重生。
