# 《奶龙：银河征途》数据契约（M0）

> 适用范围：v1.1 范围收窄版（⓪①② 三区域 / 15 房）。
> 所有权：本文件描述的六张数据表归 **Level/Balance Agent** 所有，代码侧（Architect/Gameplay）只读。
> 参考章节：开发计划书 §3.3 / §3.5–3.8 / §4.1–4.4 / §5.1–5.2 / 附录 A/B。

## 0. 总则

1. **严格 JSON**：UTF-8、无注释、无尾逗号、键带双引号。说明文字只写在本文档，不写进 JSON。
2. **一切数值进表**：代码里禁止魔法数字；改数值 = 改表 + 跑校验，不动脚本。
3. **单位**：坐标/尺寸为像素（px），速度为 px/s，时间为秒（s），`*_pct` 为百分数（如 `15` 表示 +15%，`-10` 表示 -10%），`resist` 为乘数（1.0=正常，0=免疫，>1=易伤）。
4. **校验命令**：`python3 tools/validate_data.py`，退出码 0 才允许提交（覆盖断言见第 9 节）。

## 1. 坐标与几何约定（全表通用）

| 事项 | 约定 |
|---|---|
| 房间像素尺寸 | `size = [w,h]`，实际像素 `W = w×640`、`H = h×360`；本期只允许 1×1 / 2×1 / 1×2 / 2×2 |
| 平台矩形 | `[x,y,w,h]`，矩形完全在房间边界内；**顶面 y 是可站立面**，渲染为 `_draw()` 灰盒色块 |
| 玩家碰撞体 | 20×34（半宽 10 / 半高 17，§2.5） |
| 站立点约定 | 角色类坐标（spawn、门 pos、地面敌人 pos、检查点 pos）= **碰撞体中心**，站立时 `y = 平台顶 - 17` |
| 宝箱 | 视为 24×20 盒子，pos = 中心，放置时 `y = 平台顶 - 10` |
| 门 pos | 见 §2.3；n/s 门也要求落在平台上（站在高台/地面，贴上下边） |
| map_rect | `[x,y,w,h]` 小地图格坐标（1 格 = 640×360），两两互不重叠，w/h 与 size 一致 |
| 跳跃可达参考 | 单跳升 ≈56px；平台台阶升 ≤48 视为单跳可上；升/横距 >56~90 视为需二段跳（数值以 Gameplay 实测为准，数据层只负责放置） |

### 2.3 doors[]：门与配对语义

门对象：`{id, pos, target, target_door, one_way, requires}`。

| 字段 | 类型/枚举 | 语义 |
|---|---|---|
| id | 方位惯例 | 前缀 `w/e/n/s`，同方位多门加数字后缀（如 `e2`） |
| pos | [x,y] | 玩家进入/落地的站立点。w 门 `[0,y]`、e 门 `[W-10,y]`；n 门贴上边（y≤48，站高台）、s 门贴下边（y≥H-48，站地面） |
| target | string | 目标房间 id |
| target_door | string | 目标房间里的门 id |
| one_way | bool | **true = 该门只能作为单向通道的落点，不可从此侧主动进入**（AGENTS.md §6 约定） |
| requires | "" \| "double_jump" | 能力门：未解锁该能力时门锁定（锁标+提示） |

**配对规则（校验脚本强制）**：

- 每个门与它的 `target.target_door` 必须**互指**（你指我、我指你），且方位**互补**（w↔e、n↔s）。
- 双向门：两侧 `one_way` 均 `false`。
- **单向捷径**（本期唯一一处，cave_07→camp_01）：cave_07 侧门 `s`（`one_way:false`，可通行）→ camp_01 侧落点门 `n`（`one_way:true`，锁定，仅作落点，指回 cave_07.s）。玩家击败女王后从 cave_07 落回营地，不能反向钻回洞窟。
- **能力门**（本期唯一一对）：forest_03.n ↔ forest_06.s 两侧 `requires:"double_jump"`；其余门一律 `requires:""`。二段跳来自 cave_07 宝箱（击败蜂蜜女王后）。
- 门的进出落点都要求站在平台上；SceneRouter 切房后把玩家放到目标门 pos（对齐误差 ≤4px 由代码保证）。

| cave_03 | coins 30（item 空串） | 酸池房奖励 |

## 3. data/enemies.json

顶层 `{"enemies":[...]}`，本期 12 条（8 小怪 / 3 精英 / 1 BOSS）。

| 字段 | 类型/枚举 | 语义 |
|---|---|---|
| id / name | string | 敌人 id 与中文名 |
| rank | `small`/`elite`/`boss` | 档位（§3.12） |
| tier | 1 / 2 | 所属区域等级（林地 1、洞窟 2） |
| hp / damage / defense | int | 基础数值，由 §5.2 公式生成（见下） |
| resist | {physical, magic} | 伤害类型乘数（弱点 >1 / 抗性 <1 / 免疫 0） |
| ai | object | `{type, patrol_speed, chase_speed, attack_range, telegraph_time, features[]}` |
| ai.type | `ground`/`fly`/`float`/`turret` | 地面巡逻 / 飞行 / 漂浮 / 固定炮台（turret 速度为 0） |
| ai.telegraph_time | float | 预警时长，**一律 ≥0.25**（§3.12，无预警秒杀禁令） |
| exp | int | 击杀经验 |
| coin_drop | [min,max] | 奶币掉落区间 |
| desc | string | 设计说明；BOSS 两阶段招式写在这里 |

**§5.2 数值公式（校验按此断言）**：小怪 HP `20+10×tier`、伤害 `4+2×tier`、防御 `5+3×tier`；精英 HP ×8、伤害 ×1.6 取整；BOSS HP ×45、伤害 ×2.2 取整。即：tier1 小怪 30/6/8，tier2 小怪 40/8/11，精英 240/10 与 320/13，BOSS 1800/18（防 11）。exp：tier1 小怪 8、tier2 小怪 14、精英 60/90、BOSS 400。掉落：小怪 [3,6]、精英 [30,50]、BOSS [250,250]（§3.8）。

**抗性（§3.3）**：moss_beetle 物理 0.8；shadow_wisp 法术 0（免疫）；acid_slug 物理 1.2 / 法术 0.6；honey_queen 法术 0.5；其余 1.0/1.0。

**ai.features 词汇表**：`split`（死亡分裂）、`shield`（举盾格挡正面）、`summon`（召唤蜜蜡蜂）、`dive`（俯冲）、`spray`（喷酸）、`acid_trail`（留酸地）、`glow`（自体发光）、`charge`（直线冲撞）、`sine`（正弦飞行）。新增词条需同步更新本表与 Gameplay 侧实现。

## 9. 校验脚本（tools/validate_data.py）

python3 运行、零第三方依赖。失败逐条打印 `[FAIL]`，退出码 1；全过打印 64 项 `[OK]`，退出码 0。

断言覆盖：

1. 六文件存在且为严格 JSON（注释/尾逗号即解析失败）。
2. regions 3 条 / rooms 15 条、id 唯一、bg 与 tier 按附录 B。
3. 房间尺寸 ∈ {1×1,2×1,1×2,2×2} 且与 §4.1 连接表一致；14 个必填字段齐全。
4. platforms/hazards 矩形合法且在房间边界内；spawn/门/宝箱/检查点/地面怪坐标在边界内且站在平台上（§1 站立约定）。
5. 门配对：互指一致、方位互补（w↔e / n↔s）、贴边位置惯例、id 方位命名、同房 id 不重复；`one_way` 不允许双侧 true；单向捷径恰一处（cave_07.s→camp_01.n）；`requires` 枚举合法且成对相等，能力门恰为 forest_03.n/forest_06.s。
6. 宝箱共 8、hidden 恰 2（forest_06/cave_05）、物品/数量/奶币分布与 §4.4 一致；item 引用可解析（空串则 coins>0）。
7. 房间 enemies[].id 引用可解析；15 房刷怪分布与 §4.1/§4.3 一致。
8. 检查点恰 4 个且 id 唯一；篝火/仓库/商人/教学设施分布正确；cave_03 酸池 ≥1。
