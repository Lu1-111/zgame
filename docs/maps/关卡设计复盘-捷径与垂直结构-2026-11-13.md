# 关卡设计复盘：捷径、垂直结构与重复探索

2026-11-13。制作人已否决上一轮三张概念图。本文件记录重新查阅设计资料后的复盘，作为重画之前的工作方法；不修改既有房间、能力、连接或数值，不替代已批准的开发计划与制作人地图草图。

## 1. 上一轮的根本问题

三稿有平台、敌人、宝箱、门和箭头，却没有充分说明玩家为何这样走、何时会重新经过这里、此时的能力和认知如何改变走法。

| 旧稿 | 缺失的设计关系 | 为什么影响体验 |
|---|---|---|
| A双环根庭 | 左环主要是绕根台取一个箱子；右环门未绑定具体的复战、跨区或后续回访需求 | 绕一圈和画出闭环不能独自证明探索价值；应明确远行目的、认出旧地的位置，以及开门后哪条常用路发生变化 |
| B树心竖井 | 长串交替踏台承担几乎全部上升；侧向房间、门、藏室与推进的关系很弱 | 把横向通道竖起来仍然可能只有一条走法；还错误地把全图上可见的树心当成游戏镜头里持续可见的地标 |
| C断冠分流 | “上短下长”“上险下稳”只是标注，没有用实际移动、敌人射程、消耗与退路验证 | 两条并行线未必构成有效取舍；失足后是否还能取宝、换路是否要整段重跑，也没有说明 |

门可以有减负作用，单向支线也可以成立，简单房间同样有价值。但这些作用需要在真实路线、进度和使用场景中证明，不能只靠给形状命名。

## 2. 查阅到的具体设计事实

以下先列资料中的事实，后文的方法和对本项目的应用属于本次分析。

### 《空洞骑士》：连接与技巧共同参与路线

Team Cherry谈到早期以十字路为世界中心组织周边区域；最终仍重视地理连续性和区域间连接。访谈还提到苍绿之径刻意放置飞行敌人，让玩家引来反弹、跳过下方绕路。这是移动技巧、敌人位置与地形一起改变路线的具体例子。[开发者访谈，PC Gamer](https://www.pcgamer.com/how-to-design-a-great-metroidvania-map/)

本次分析：观察地图要区分世界连接、区域走法、单房移动三个层次。一个区域可以总体顺序明确，同时在局部保留技巧路线；增加物理出口或敌人位置，也可能比增加一扇能力门更有效。

### 《死亡细胞》：区域形态承担玩法目的

Sébastien Bénard的开发日志举例说明：下水道用狭窄空间限制跳跃和闪避，城墙区域的结构则更直接；房间块也按战斗、商人、宝藏等目的区分。生成前先确定结构图与房间约束。[主设计师原文，IndieDB](https://www.indiedb.com/games/dead-cells/news/the-level-design-of-a-procedurally-generated-metroidvania)

本次分析：敌人密度相同，放进窄道、错层洞厅、连续平地会形成不同的走位问题。借鉴时应先说明空间如何影响现有动作、敌人和退路，再讨论平台数量。其单局推进结构与本项目的永久地图回访需求应分别评估。

### 《密特罗德 生存恐惧》：初访与回访一起设计

开发团队说明，区域布局和事件、敌人、能力、秘密的布置，会同时考虑初次进入和以后带着新能力回来。官方探索说明还强调，主线隐藏通路有敌人、可见的通道或声音等线索，新能力也会使旧区域出现新的前进机会。[开发团队说明，Report 10](https://www.nintendo.com/au/news-and-articles/metroid-dread-report-vol-10-to-those-departing-for-zdr/)、[探索说明，Report 11](https://www.nintendo.com/au/news-and-articles/metroid-dread-report-vol-11-power-through-with-these-pointers-for-exploration-and-combat/)

本次分析：初访时留下的障碍必须能够被辨认和记住；回访的收益可以是新区域、另一条主路、资源路线或熟悉空间里的更流畅移动。不能只在角落放一个标注“二段跳”的箱子，就认为完成了能力回访设计。

### 《丝之歌》：垂直落入也能参与非线性推进

Mark Brown在其亲自进行的路线拆解中指出，同一关键移动能力所在的Cauldron有不同抵达方式，其中一条经另一地区从上方落入。这里参考的是分析作者整理的路线关系，而非将其评价当作开发者规则。[GMTK原始分析，Part 3](https://gmtk.substack.com/p/the-world-design-of-hollow-knight)

本次分析：高低关系能够为同一目的地提供不同入口，进而影响挑战顺序、能力获取顺序和回程。纵向房间的设计价值取决于这些联系，不能用总高度或楼层数量代替。

## 3. 捷径应先回答“谁会在什么时候使用”

### 3.1 明确两端和使用目的

设计一条候选捷径时，先写出：

- 它连接哪两个有意义的位置：复活点与复战区、区域枢纽与深处、两个旧区域，还是资源支线与主路？
- 玩家为何还会经过这两端：失败重试、交任务、继续探索、跨区回访，或回营整备？
- 原路径已经让玩家掌握了哪些内容？捷径跳过的是已学会的重复段，还是尚未体验的关键内容？
- 初次如何到达远侧？开通后是否双向、是否永久保留？
- 是否被已有篝火旅行完全替代？若被替代，步行连接还保留什么价值？

门、桥、升降机、落井和能力穿越都可以改变通行关系。这里列举的是空间手段，后续实施仍只能使用项目已支持或经制作人确认的机制。

### 3.2 开通时机决定捷径的作用

以“篝火—探索段—门的远侧—后续挑战”为抽象例子：

```mermaid
flowchart LR
    S[篝火 / 熟悉位置] --> A[下层探索]
    A --> B[侧洞与攀升]
    B --> C[抵达门的远侧]
    C --> T[后续挑战或新区]
    C -. 首次从远侧开启，随后双向 .-> S
```

第一次需要通过A、B认识空间。开门后，从S去T能经C抵达，A、B仍保留支线或资源价值。

若目的是减轻T的失败重跑，应让玩家在进入T之前有机会开门。若只有打赢T才能开门，它主要服务通关返程和后续回访，不能将其作用描述为减轻T的复战负担。

这里的图只是关系示例，没有预设新房间，也没有假定每张地图都应采用此形状。

### 3.3 必须比较前后路线

灰盒中用相同能力和移动条件，比较关闭/开启两种状态：

| 检查项 | 要观察什么 |
|---|---|
| 行进时间 | 步行、攀爬、门交互、升降机等待等实际耗时 |
| 重复操作 | 已掌握的跳跃和重复战斗是否仍然占用主要时间 |
| 风险与资源 | 重试前需要付出的战斗、失误和补给代价 |
| 可读性 | 开门后玩家能否认出自己回到了哪里，理解连接了什么 |
| 利用机会 | 之后确实会再用，还是开完就离开、用途只存在于说明文字中 |

不预设一个适用于所有捷径的缩短百分比。先证明其服务目的，再根据实际流程调整。

### 3.4 区分不同类型的通行变化

- **永久开通**：改变长期路网，例如从另一侧打开的门。
- **单向落差**：初始只有向下通行；能否返回需要单独设计。它可能是承诺、引导或短路，但不能自动算作双向捷径。
- **能力路线**：获得能力后让原有地形可跨越。要验证其他动作是否已经能绕过条件。
- **战斗封印**：组织遭遇与清场进度。是否也构成捷径，要看清场后改变了哪条常用路。
- **快速旅行**：连接服务点。应和步行捷径一起评估，避免设计用途相互抵消。

## 4. 垂直结构要组织方向、分层出口与信息

### 4.1 上升、下降和返程分别设计

上升要求落脚点、腾空距离与走位空间；下降可以跨过多个高度，但会改变玩家对退路与未知落点的判断。同一个井，在初访向下、绕行向上、获得能力后逆行时，可以承担不同作用。

落差若构成承诺，下面必须有符合当前能力的出路。玩家可以暂时失去直接回头的能力，但不应因没有某项尚未获得的能力而永久困住。

### 4.2 不同高度的出口必须有具体用途

一座竖向枢纽可在下层连接入口，中段连接休整、另一侧洞厅或回环，上层连接推进路线。但每个出口应说明通往什么、何时开放、会从哪里回来。没有这些联系，侧门也只是贴在竖井上的装饰。

也不要求每一层都开门。某一段专注攀爬、观察或短战斗可以成立，关键是段落在整个区域中的作用。

### 4.3 利用高低之间的可见性

要分别记录：

- 玩家当前能站在哪里；
- 从该位置、当前镜头里能看到什么；
- 哪些看到的目标现在可达，哪些需要绕行或能力；
- 绕到目标后，会从哪个熟悉的地形、灯光、建筑或声音认出原来的位置。

设计者在全图上能同时看见两处，不代表玩家在屏幕内能看见。上一轮B图的“树心始终可见”没有做这一层验证。

### 4.4 地形和敌人共同决定垂直战斗

高台可以提供落脚、观察和选择进场角度的机会；飞行敌人能够接触多个高度，地面敌人则受平台边缘和追击能力影响。需要检查：腾空期间有哪些攻击可能覆盖、落地后有没有反应空间、追击是否会跨层、返回时能否避开已经掌握的遭遇。

敌人应有空间用途。并非每块台子都需要放怪，也不能只靠把怪移到窄台上提升难度。

### 4.5 0.9跳高属于可达约束

平台升高不超过0.9单跳高度，能约束基础可达性，但还要考虑水平位移、身体碰撞、顶棚、起跳余量和着地余量。层间高差不必都贴着上限：地面、短台、跨层落差与局部攀爬应根据空间用途组合。

正式设计还应区别薄台上穿/下穿与实体平台绕边：同一个高度关系，二者产生的路线和操作差异很大。

### 4.6 空间形态要有地理或用途依据

Team Cherry在访谈中用蓝湖位于泪水之城上方来解释降雨来源，展示了世界上下关系怎样与环境逻辑结合。[开发者访谈中的蓝湖例子](https://www.pcgamer.com/how-to-design-a-great-metroidvania-map/)

本项目后续提案应先确定具体的空间来源，例如巨根与岩壁之间形成的洞隙、被根系顶裂的旧建筑，或天然落差连接的湿地。再据此决定哪里有宽洞厅、狭口、可站立的实体支撑和侧向出口。不能等画好一列踏台后，再通过命名和装饰补出“古树”的理由。具体题材仍是待评估提案，不在本轮直接加入场景。

## 5. 能力与认知如何改变旧空间

重画时至少区分以下状态，数量按实际流程决定：

1. **初访**：拥有基础动作，尚未识别全部连接。可以去哪里，看见了哪些暂不可达目标？
2. **区域探索完成**：门与回环已开，开始重复往返。现在常用哪条路，旧路还保留什么用途？
3. **获得已有规划能力后**：新的移动范围连通了哪些旧边界？推进顺序、跨区路线或局部走法是否改变？

不要求每项能力都重排整张世界，也不要求每条支线都回到主路。重点是让每项预告和回访收益有因果关系，并保持总体推进可读。

地图画成网状不等于玩家具有选择。若所有分支在当前状态都锁住，实际走法仍可能是单线；反之，整体目标顺序明确的地图，也可以通过局部绕行、探索和技巧路线提供主动性。

## 6. 应用于本项目时的约束

- 当前可用动作包括基础跳跃、薄台下穿和空中闪避；二段跳由能力解锁。没有已确认的蹬墙跳、飞敌反弹或滑翔，不能把这些动作暗含进新地图。
- 代码锚点为 `scripts/player/player_tuning.gd`、`scripts/player/player.gd`、`scripts/player/player_states.gd` 与 `data/player_movement.json`。空中闪避也会影响跨隙能力；能力门不能仅按垂直高度判断。
- forest_02/03上下双通道应在跨房间关系中评估：下层先连通，上层从03侧开启后增加一条永久连接。这和在单房里画一个绕圈的意义不同。
- 当前篝火兼有恢复、复活与旅行等功能，捷径必须结合这些服务点分析。
- 角色、敌人、平台和镜头都采用实际运行尺度来验证；新提案不能只在缩小的全图上成立。
- 不擅改现有地图或为研究增加未批准的移动能力。本文件提出的检验问题也不自动变成每张地图的配额。

## 7. 下一版草图应提供的证据

重画先从一张候选的结构与使用过程开始，提交以下内容：

1. **区域连接图**：与既有房间的关系、入口、目标、服务点、能力条件和永久开通状态。
2. **状态变化图**：初访、开通后、能力回访分别怎么走，在哪些位置作决定。
3. **捷径前后对照**：明确两端、开通时机、未来用途与省去的重复段。耗时先在灰盒测量，未测不填虚构实测数。
4. **垂直剖面与关键镜头**：上升和下降的路线、不同高度出口、可见不可达目标、落点与返回方式。
5. **灰盒走查**：可达性、能力门绕过、单向落差出路、复活重跑和战斗/镜头联动，再据此调整。

这些证据成立之后再细化宝箱、敌人位置与装饰。原三稿保留为被否决的讨论记录，原有B优先推荐已撤回。
