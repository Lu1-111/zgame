# 启动卡顿排查

制作人反馈标题页即出现整机卡顿，关闭游戏后立即恢复。

系统只读采样显示：约 16GB 物理内存中可用约 0.8GB，提交内存约 50.5GiB / 上限 55.3GiB，换页计数约 4883 页/秒；一个 Java 进程的工作集约 6.1GiB。项目原先未设置帧率硬上限。这些是已观测的资源压力，尚未确认原始卡顿由单一因素引起。正式用户日志中的引擎退出错误也不能据此直接认定为卡顿根因。

已在 `project.godot` 显式设置 60 FPS 上限、垂直同步及省电模式 33333µs 间隔；标题页开启按需重绘，离开标题恢复原模式。物理仍为 60Hz。依据：[Godot 帧率设置](https://docs.godotengine.org/en/stable/classes/class_projectsettings.html#class-projectsettings-property-application-run-max-fps)、[OS 按需重绘](https://docs.godotengine.org/en/stable/classes/class_os.html#class-os-property-low-processor-usage-mode)。

`test/integration/test_startup_performance.gd` 的限时离屏图形测试使用真实 OpenGL 渲染、1280×720 分辨率和隔离用户目录。外部看护直接监控 GUI 引擎进程，15 秒超时、700MB 工作集阈值，限制辅助进程优先级；未触发看护终止。进程工作集峰值约 230MB，稳定期标题约 30 FPS，窗口响应检测全部为 True；退出标题后恢复原运行模式，退出码 0，无错误或警告。这里不是仅监控 `_console.exe` 启动器的占用。

本次测试未复现用户可见窗口完全无响应，因此不声称已经证明全部根因。此前无界面冒烟通过，也不能代替前台运行流畅性验证。未结束其他应用或修改正式存档。
