# 项目目录与发布流程

制作人2026-11-16要求：测试内容集中到根目录test；源仓库只保存游戏相关文件；明确版本号更新时同步源码并单独发布可运行beta。

## 查找文件

| 目录 | 内容 |
|---|---|
| scenes/main.tscn | 正式标题与启动场景 |
| scenes/maps/ | 实际运行的营地、森林地图及公共房间壳 |
| scenes/player、enemies、npcs、ui/ | 正式实体和界面场景 |
| scripts/ | 生产代码，按autoload/core/components/player/enemies/ui/world分类 |
| data/maps/ | 地图几何、门、平台、敌人与对应_art表现表；相同地图ID配对 |
| data/world/ | 区域登记、地图布局、世界地图配置 |
| data/bosses/、其他data/*.json | Boss、战斗、成长与系统数值 |
| assets/RAW/ | 原始素材；按characters/enemies/skills/items/environments/effects分类 |
| assets/PROCESSED/ | 已处理及储备素材；同样按内容类型、批次、版本分类 |
| assets/environments/ | 游戏专用backgrounds/terrain/tilesets/props；按地图或共享版本细分 |
| assets/effects、ui、audio、fonts、characters/ | 特效、界面、音效、字体和其他运行资源 |
| assets/ui/map/minimaps/ | 运行时使用的小地图，不能当作普通预览删除 |
| assets/third_party/ | 第三方关卡素材及出处 |
| test/scenes/ | arenas演练场、previews美术场、harnesses模拟宿主、fixtures测试靶、assets素材包预览 |
| test/unit、integration、fixtures、scripts、previews/ | 单元、物理验收、测试替身、测试场景脚本、预览脚本 |
| test/launchers/ | 直接进森林或Boss演练的.cmd/.sh入口 |
| tools/assets、maps、data、qa、release/ | 素材加工、地图构建、数值同步、校验、发布 |
| docs/maps、gameplay、art、engineering/ | 地图、玩法、美术和工程说明 |
| docs/concepts/ | 未实施的备选草图、设计数据和评审记录 |
| docs/previews/ | 评审用图片、视频，不供运行时读取 |
| work/ | 本机日志、隔离存档、缓存、中间产物；不入库、不导出 |

根目录只保留project.godot、README、AGENTS、Git规则及正式run_game入口。已有但未应用的技能、怪物、NPC、美术母版均保留；未完成的装饰像素化配置已归档到docs/art/drafts，不作为正式data配置。

## 验证与运行

正式启动：双击根目录run_game.cmd。测试入口现在位于test/launchers。

```powershell
tools/qa/run_godot.ps1 -Name import -GodotArgs @('--headless','--editor','--import','--quit') -MemoryMB 1800
tools/qa/run_godot.ps1 -Name units -GodotArgs @('--headless','--script','res://test/run_tests.gd')
python tools/qa/audit_repository.py
python tools/qa/validate_data.py
python tools/data/sync_enemy_registry.py --check
python tools/release/prepare_beta.py --check
```

Godot4.7.2本机路径为D:/Tools/Godot/Godot_v4.7.2-stable_win64.exe；允许GODOT_BIN覆盖。检查助手隐藏运行、限制时长和内存、降低优先级，并使用work/qa独立存档，避免覆盖玩家存档。

## 明确版本更新时发布

触发条件是制作人明确说明“进行版本更新”并给出版本号；普通修改、草图评审不触发上传，也不擅自创造版本号。

1. 更新版本记录，完成导入、单元、资源、数据及本次变更的物理验收。
2. 按生产依赖生成独立干净导出工程，不复制test、docs、tools、work、RAW、制作预览、存档和缓存。储备素材保留在源码仓库，只有运行所需资源进入beta。
3. 使用Windows x64 release导出模板生成可双击运行的exe和资源包，运行导出后冒烟；不能以源码ZIP或单独PCK冒充可用beta。
4. 生成beta ZIP、SHA256和发布说明；再提交源码，推送当前分支及不可覆盖的版本标签。
5. 将beta和校验文件单独上传到同一GitHub版本的预发布Release；源码和成品分开。

入口：tools/release/publish_beta.ps1 -Version 制作人给定版本号。依赖GitHub CLI登录及与Godot4.7.2匹配的Windows导出模板；缺少模板或构建失败时停止发布，保留日志和本地阶段产物。当前机器尚未安装导出模板；到明确版本发布时先补齐，再导出和上传。远端为https://github.com/Lu1-111/zgame。

重复版本、标签不得覆盖；网络失败后重试已有提交/Release的未完成上传，不重复创建版本。自动脚本上传前的检查和构建不替代相关物理验收。

Godot导出模板、可执行导出和PCK区别参考[官方导出说明](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html)，参数参考[官方命令行说明](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html)。
