## 1. 一页总览

| 3 | `DataDB` | `scripts/autoload/data_db.gd` | ✅ 完整 | 启动 `_ready()` 即 `load_all()` 载入 `data/*.json`，按 `StringName` id 建索引；`get_region/get_room/get_item/get_weapon/get_skill/get_talent/get_enemy/get_rooms`，**查询缺失一律返回 `{}`**；regions.json 失败 → `loaded=false` 并返回错误码，其余表缺失/坏结构仅 `push_warning` 一次 |
| 4 | `SaveSystem` | `scripts/autoload/save_system.gd` | 🔶 骨架 | 存档目录 `user://saves/`、版本号常量；`has_save/delete_save` 可用；`save_game` 返回 `ERR_UNAVAILABLE`、`load_game` 返回 `false`——TODO(M2)：序列化落盘 + CRC + 双槽轮换 + `.bak` + 发 `EventBus.save_completed`。铁律：禁止战斗中自动存档 |
| 5 | `SceneRouter` | `scripts/autoload/scene_router.gd` | 🔶 骨架 | `goto_room()` 是 `pass`——TODO(M2)：0.25s 黑场转场、门对齐 ≤4px、转场自动存档、取 `DataDB.get_room` 交 RoomBuilder；`change_scene()`（换任意场景文件）M0 可用，M1 已被标题屏↔试玩场流转实际使用 |
| 6 | `AudioManager` | `scripts/autoload/audio_manager.gd` | ✅ 完整 | `play_sfx/play_bgm/stop_bgm(淡出)`；在 `assets/audio/{sfx,bgm}/` 按 id 同名查找（ogg/wav/mp3 依次尝试）；**资源缺失属灰盒期预期**：同一 id 只 `push_warning` 一次后静默返回；SFX 播放器按需扩容 |

**为什么是这个注册顺序**：Godot 按 `[autoload]` 段的书写顺序依次实例化单例，后注册者可在自己的 `_ready` 里安全引用先注册者，因此顺序 = 依赖链：`EventBus` 无依赖且被所有人引用（信号解耦）→ `GameState` 是状态源、会发事件 → `DataDB` 只读数据（被 SceneRouter 查询）→ `SaveSystem` 依赖 `GameState`（序列化它）与 `EventBus`（存档完成信号）→ `SceneRouter` 依赖 `DataDB`（查房间表）+ `GameState`（房间/检查点状态）+ `SaveSystem`（转场自动存档）→ `AudioManager` 独立（只读 assets，放最后）。**新增 autoload 须沿用此原则，且 AGENTS.md 规定不得擅自新增。**

#### 连贯性规则表（谁能取消谁）

统一入口 `try_actions()`：自由态每帧先问它，优先级 **跳 > 闪避 > 普攻 > 技能 > 防御**（防御为按住式，不走缓冲）。

| 状态 | 取消/衔接规则 |
|---|---|
| 自由态（Idle/Run/Jump/Fall/Land） | 全开放，任意动作即时衔接；Land（0.05s 落地缓冲）随时可被输入打断 |
| Attack | 起手+判定窗（0–0.22s）锁定不可取消；判定窗结束进后摇后可被【**连击 / 闪避 / 技能**】取消（跳不可）；连击续拍仅限非末段且需连击中再按攻击写入的 `attack_chain` 标记；后摇走完自动回自由态 |
| Skill | 起手 0.08s（弹体出手前）锁定；**弹已出手**即进后摇，可被【**闪避 / 普攻**】取消（跳不可） |
| Dodge | **全程锁定** 0.18s（重力冻结的水平位移承诺）；结束回自由态，残留缓冲由 try_actions 立即消费 |
| Guard | 地面按住右键进入；可被【**普攻 / 闪避 / 技能**】缓冲取消（防反衔接）；松键或离地回 Idle |
| Hurt / Dead | 硬直锁定（0.2s；破防 0.6s），结束回自由态；Dead 1.5s 后自动重生（HP 满、体力/奶力半满、回检查点、1s 无敌） |

**缓冲统一约定**：just_pressed 写入缓冲（跳 0.12s / 普攻 0.12s；连击中再按普攻走专用 1 槽 `attack_chain`）；消费遵循 **peek 成功才 consume**——动作暂不可用（空中无二段跳、闪避冷却中、奶力不足）**不吞缓冲**，让它存活到条件满足（计划书 §3.1 验收 2）。普攻缓冲无条件消费（Attack 总是合法），防御按住即进不走缓冲。

#### 积分器：半步重力（leapfrog）

`_physics_process` 的顺序是：状态 tick（含跳跃脉冲赋速）→ 加 `g·dt/2` → `move_and_slide()` → 再加 `g·dt/2`。半步积分让离散求和的跳高逼近连续解析值 **v²/2g = 450²/(2×1800) = 56.25px**（计划书 §3.1 验收 4，容差 ±2px，由 sim_player 实测断言）；普通前向欧拉积分会带系统性偏差。上升重力 1800 / 下落 2600（落得比升得快）/ 落速上限 700。Dodge/Dead 期间 `gravity_enabled = false` 整体关闭重力（保证闪避水平位移承诺）。

**攻击特效实体与鼠标瞄准（2026-10-24，两子代理并行交付）**：① 攻击/技能触发时角色自动转向鼠标点击方位（`player.aim_vector()`），连击每拍重取；② 近战/挤奶冲击的伤害判定从玩家身上静态 Hitbox 改为**发射 AttackEffect 特效实体**（`scripts/core/attack_effect.gd`：特效视觉 + 自带接触判定框，伤害结算在特效位置；内部封装 FX-B01 EffectPlayer 播放、effect_completed 驱动回收、素材缺失回退灰盒）；锤三段映射 `hammer_swing_1/2`、`hammer_slam_3`，奶杖借用 swing_1（无专属特效）；③ 弹道 2D 化：projectile `dir` 改 Vector2，全部发射走鼠标方位（奶弹 420/法球 260/奶泡/道具奶弹），命中与撞墙点播 `physical_hit`/`magic_hit` 冲击特效；④ 玩家 `$AttackPivot/Hitbox` 保留不激活（判定已移至特效实体，归属过滤照旧防自伤）。特效实体契约冻结：`AttackEffect.spawn(...)` / `play_impact(...)` / `hit_landed` 信号，后续敌人攻击特效复用同一实体（source_actor 换敌人即得敌我判定）。

## 3. 数据流：JSON → DataDB → 游戏逻辑

```
data/*.json（6 个文件，Level/Balance Agent 所有，严格 JSON 无注释无尾逗号）
      │  Godot 启动，autoload 初始化
      ▼
DataDB._ready() → load_all()（可重复调用，先清空再载入）
      ├─ regions.json ──► regions[]（保序）＋ rooms{ id → 房间 dict }
      │     失败（缺失/解析错）＝ loaded=false，返回 ERR_*，push_warning 一次，不崩溃
      └─ items/weapons/skills/talents/enemies.json ──► 各自 { id → 条目 dict }
            文件缺失 / 顶层键异常 / 非数组 ＝ push_warning 一次，跳过该表
      ▼
游戏逻辑（scripts/{player,enemies,ui,core,world}/…；M1 起玩家控制器是消费方）
      │  DataDB.get_room(&"forest_01") / get_enemy(&"moss_beetle") / get_weapon(&"hammer_01") / get_skill(&"skill_bubble") / …
      ▼
缺失一律返回空 Dictionary {} —— 调用方必须判空（`if d.is_empty():`）
```

要点：

- **唯一的数据入口是 DataDB**。任何代码不得自己 `FileAccess` 读 `data/`（测试/工具脚本除外）。
- id 在 DataDB 内统一为 `StringName`；查询用 `&"forest_01"` 字面量或 `StringName(字符串)`。
- `regions.json` 是"世界是否可用"的开关（`DataDB.loaded`）；五张内容表缺失只降级不崩溃——这是灰盒期关卡/数值 Agent 并行改表的容错保障。
- schema 与字段语义以 `docs/数据契约.md` 为准（六表逐字段表格 + 校验断言清单）。

### "改数值不改代码"的具体操作路径

铁律：改表 → 跑 `python3 tools/validate_data.py` → exit 0 才算改完。**但注意**：validate_data.py 把一批"计划锚点"数值写死在期望表里（`docs/数据契约.md` §9 末尾注明：改锚点须同步"JSON + 校验脚本 + 契约"三处）。所以分两类：

**① 自由字段（只改 JSON，校验直接过）**：

| 想改什么 | 动哪个文件哪个字段 |
|---|---|
| 苔甲虫巡逻/追击速度、索敌距离、预警时长 | `data/enemies.json` → `moss_beetle.ai.patrol_speed / chase_speed / attack_range / telegraph_time` |
| 房间地形（平台/酸池矩形，守边界与站立约定） | `data/world/regions.json` → 对应房 `platforms / hazards` |
| 房内飞/浮怪位置（边界内即可） | 同上 → 该房 `enemies[].pos` |
| 武器/技能/道具的中文说明 | 各表 `desc` 字段 |
| 区域/房间底色 | `regions[].bg`（房间 bg 须等于所属区域 bg，一起改） |

**② 锚点字段（改 JSON 会校验 FAIL，必须三处同步）**：

| 想改什么 | JSON 字段 | 还要同步 |
|---|---|---|
| 苔甲虫血量 | `data/enemies.json` → `moss_beetle.hp` | `tools/validate_data.py` 的 `EXPECTED_ENEMY_STATS` + `docs/数据契约.md` §3（hp 被 §5.2 公式 `20+10×tier` 锚定） |
| 加一个宝箱 | `regions.json` → 对应房 `chests[]` | `validate_data.py` 的 `EXPECTED_CHESTS`（宝箱总数=8、hidden 恰 2、逐箱内容都锚定）+ 契约 §2.4 |
| 改天赋价格 | `data/talents.json` → `cost_coin` | `validate_data.py` 的 `TALENT_COST_BY_TIER`（层价 100/130/160/170、三支合计 1680 锚定）+ 契约 §7 + 计划书 §3.8 预算 |
| 武器伤害/攻速 | `data/weapons.json` → `attack / attack_interval` | `validate_data.py` 的 `EXPECTED_WEAPONS` + 契约 §5（契约注明 M1 手感调参可改，但三处要一起动） |

## 4. 怎么加内容（纯数据，零代码）

> 前提认知：当前 15 房/12 敌/13 道具等**数量与分布本身是校验锚点**。所以"零代码"但**不是零同步**——新增内容 = 改 JSON + 同步 validate_data.py 期望表 + 同步数据契约（必要时连计划书），然后校验归零。代码侧在 M2 RoomBuilder 建成后自动消费，永远不用动。

### 4.1 新增一个房间

1. **先在计划书层面定拓扑**：新房间与哪几房相连、门在哪个方位、有无能力门/单向捷径（守 §4.1 连接表风格）。
2. **`data/world/regions.json`**：
   - `rooms[]` 追加完整条目，**14 个必填字段**一个不少：`id, name, region, size, bg, platforms, spawn, doors, enemies, chests, hazards, checkpoints, features, map_rect`（缺一个都过不了校验）。
   - `size` 只允许 1×1 / 2×1 / 1×2 / 2×2（像素 = 格数 × 640×360）。
   - `bg` 必须等于所属 `region` 的 bg。
   - **门配对**：新门的 `target`/`target_door` 必须与对方门**互指**，方位**互补**（w↔e、n↔s）；id 用方位前缀（同侧多门 `e2`…）；位置贴边惯例：w 门 `x=0`、e 门 `x=W-10`、n 门 `y≤48`、s 门 `y≥H-48`；**所有门 pos 必须站在某块平台上**（站立约定见契约 §1：pos 是碰撞体中心，`y = 平台顶 - 17`）。同时给相邻房间加反向门。
   - `one_way` 双侧不得同时 true（单向捷径 = 出发侧 `one_way:false` + 落点侧 `one_way:true`；本期唯一锚点是 `camp_01.n`）；`requires` 两侧必须相等且只允许 `""`/`"double_jump"`（本期能力门锚点是 forest_03.n/forest_06.s）。
   - `map_rect`：小地图格坐标，`w/h` 必须等于 `size`，与现有 15 块**互不重叠**（看契约 §2.2 的布局总览图找空位）。
   - `spawn` / 检查点 / 地面与炮台怪的 pos 都要站在平台上；宝箱 pos = 中心，`y = 平台顶 - 10`。
3. **同步 `tools/validate_data.py` 期望表**：`EXPECTED_SIZES`（15→16 房： rooms 数量断言、id 集合断言）、`EXPECTED_ENEMIES`（新房刷怪分布）、`EXPECTED_FEATURES`（若有篝火/商人/教学）、`EXPECTED_CHESTS`（若有宝箱）、`EXPECTED_CHECKPOINTS`（若有篝火检查点）、连通性断言（新房需可达）。
4. **同步 `docs/数据契约.md`** §2（布局总览图、门与宝箱表）。
5. **跑 `python3 tools/validate_data.py` → 64+ 项全 `[OK]`，exit 0**。

### 4.2 新增一个敌人

1. `data/enemies.json` 追加条目，字段见契约 §3（`rank` 小怪/精英/BOSS、`tier`、`hp/damage/defense`、`resist{physical,magic}`、`ai{type,…,features[]}`、`exp`、`coin_drop[min,max]`、`desc`）。
2. 数值想按公式来就代入计划书 §5.2（`小怪 HP=20+10×tier`，精英 ×8 / 伤害 ×1.6，BOSS ×45 / ×2.2）；**偏离公式即改锚点**，同步 `validate_data.py` 的 `EXPECTED_ENEMY_STATS / EXPECTED_RESIST / EXPECTED_AI_FEATURES` + 契约 §3。
3. 硬性规则：`ai.type` ∈ ground/fly/float/turret；`telegraph_time ≥ 0.25`（无预警秒杀禁令）；`ai.features` 只能用契约 §3 词汇表已有词条——**新词条 = 新契约条目 + 新 Gameplay 实现**，不是纯数据操作。
4. 要上房间刷怪表：改 `regions.json` 对应房 `enemies[]` + `validate_data.py` 的 `EXPECTED_ENEMIES`；地面/炮台怪 pos 站平台，fly/float 只要在房间边界内。
5. 校验归零。运行时行为要等 M1 敌人基类实装后才会体现。

### 4.3 新增道具 / 武器 / 技能 / 天赋

|---|---|---|
