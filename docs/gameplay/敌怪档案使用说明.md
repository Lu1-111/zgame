# 敌怪档案使用说明

全部敌怪采用独立于素材名的固定四位数字ID。登记表为[data/enemy_registry.json](../../data/enemy_registry.json)，当前0001～0024；旧ENM编号可能在不同版本代表不同物种，不能用它作为敌怪身份。同一Boss的阶段共用ID；骨龙的三种武器变体分别编号。岩穴猎手0023属于精英怪。

填写入口：[小怪记录](小怪记录.md)、[精英怪记录](精英怪记录.md)、[Boss记录](Boss记录.md)。每份均列基础属性、掉落、招式及动作时序、AI/感知/碰撞、弹幕、原生美术规格和保留素材版本。正式战斗、未实装设计和旧素材预览各有说明；旧预览的fps不能当成正式招式有效判定时间。

只填写参数表的“设定值”列，保留字段、编号与行。未设定保留“待填写”。数量、秒数、速度直接写数字；向量或范围沿用`[宽,高]`等JSON列表格式；物品掉落表按列表填写，例如`[{"item_id":"已有物品ID","count":[1,2],"probability":0.1,"condition":"条件"}]`。该例仅说明格式，不是本项目的掉落设定。物品抽取、未实装招式和储备敌怪仍需对应运行逻辑，填值不会自动实现招式。

填写后从工程根目录执行：

```text
python tools/data/sync_enemy_registry.py --import-docs
python tools/data/sync_enemy_registry.py --check
```

回填会先检查三份文档全部改动，再写JSON。非法类型、抗性超100、生命非正数、攻击窗口超出动作、共享参数冲突、未定义区域等级或源数据已变化均拒绝回填；只读素材参数不能在这里修改。共享字段只改一份即可。不要在回填前执行不带参数的重新生成命令，否则会覆盖填写。

直接调整JSON后的同步命令：

```text
python tools/data/sync_enemy_registry.py
```

新敌怪必须追加编号，禁止按排序重排。先补设计或素材登记，再运行以下命令；名称和分类按实际填写：

```text
python tools/data/sync_enemy_registry.py --register-new runtime_id --category small --name 敌怪名称
```

分类只可为small、elite或boss。已有身份拒绝重新编号。尚未接入战斗的记录不能作为地图战斗实例出生；接入时补齐基础生命、攻击、韧性、两类抗性、招式和掉落，再同步文档并通过检查。新增素材身份未登记、地图使用未知或未接入身份会使检查失败。

地图中的enemy_id可使用运行标识或四位数字字符串。敌人从实际地图的region取得区域等级，等级倍率在[data/enemy_scaling.json](../../data/enemy_scaling.json)，区域修正在[data/world/regions.json](../../data/world/regions.json)。出生时只将base_数值乘等级倍率及区域修正，生命/攻击取整，不改基础档案。防御、韧性、双抗、速度、动作时间和奖励不随等级隐式改变。当前等级0、1、2倍率均为1.0；新增等级须先填倍率表。正式地图和十张forest备选均走同一解析入口，独立试玩不会误取玩家上一张地图的区域。
