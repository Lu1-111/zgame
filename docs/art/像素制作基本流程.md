# 像素制作基本流程

制作人2026-11-17要求已纳入AGENTS.md第2节基本原则，所有后续新增/修改美术都遵守。

1. 先确定原生数据。data/art/pixel_standards.json固定640×360屏幕、前景1:1、32色上限、硬alpha及允许转换工具。每包pixel_spec固定准确画布与色板，pixel_packages.json登记包清单和文件数量。不同体型可用不同画布，主角42px可见身高是密度参照，不能把所有PNG机械改成64×64。
2. 生成图只作为RAW。新增洞穴敌怪已按制作人追加要求改为ImageMagick Point点采样、各包共享16色、无抖动、独立alpha蒙版，配置data/art/cave_enemy_imagemagick.json；不得被旧面积采样器覆盖。模型画出的方块外观不是成品像素。已有不规则网格使用recover_pixel_grid.py，依赖固定proper-pixel-art 2.0.0；没有可恢复网格且需项目尺寸重采样的母版使用pixel_grid.py或已登记固定网格批处理器。真实执行后保存源像素数、固定网格/比例、色板和输出尺寸。
3. 动画共用网格与锚点。禁止每帧auto检测、每帧裁边后各自缩到42px、按武器外伸调整身体比例。专用恢复后只允许固定偏移补透明画布，越界直接失败；项目目标重采样只能一次到最终整数网格，禁止反复缩放。
4. 原生查看通过后登记数值。运行tools/assets/register_pixel_metrics.py --manifest <包JSON>，在data/art/pixel_contracts保存逐图准确W×H、有效范围、锚点、1:1缩放与色数上限。此登记命令不修改图像，也不能由测试自动执行来覆盖预期值。
5. 执行tools/qa/validate_pixel_packages.py。实际尺寸/有效范围必须匹配数据，色板/alpha/缩放/工具记录都必须合格，任一不符非零退出。仍需看实际1×引擎画面、4×nearest检查图、完整动作及地面接触；自动统计无法判断骨骼、持握或动作是否合理。

工具实际试验与可复现命令见[audits/pixel_tool_trial-2026-11-17.md](audits/pixel_tool_trial-2026-11-17.md)。专用软件的自动猜测也会失误：两张相邻骨龙帧独立auto得到87×88和77×86，改用批次公共网格才同为49×55。因此工具必须服从项目数值和人工查看，不可“跑过工具就算合格”。
